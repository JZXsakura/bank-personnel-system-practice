# Техническое руководство по проекту

## 1. Общая информация

Проект представляет собой учебный прототип информационной системы по учету персонала в банке.
Система предназначена для демонстрации основных возможностей автоматизации кадрового учета: хранения данных о сотрудниках, просмотра подразделений, работы с карточкой сотрудника, поиска и фильтрации персонала, а также отображения статистики.

В рамках проекта были разработаны две основные части:

* статический сайт проекта;
* прототип пользовательского интерфейса информационной системы.

Статический сайт описывает тему, цель, задачи, участников и ход выполнения проекта.
Прототип информационной системы демонстрирует возможный внешний вид будущего веб-приложения для HR-отдела банка.

## 2. Используемые технологии

В проекте используются следующие технологии:

* HTML - создание структуры веб-страниц;
* CSS - оформление интерфейса и адаптивная верстка;
* JavaScript - реализация простых интерактивных функций;
* Markdown - оформление документации;
* Git - контроль версий;
* GitHub - хранение репозитория и совместная работа;
* GitHub Pages - публикация сайта проекта.

### 4.1. Страницы сайта

Страница с информацией об участниках команды.

#### `site/journal.html`

## 5. Прототип информационной системы

Прототип информационной системы расположен в папке `src/`.

Он имитирует интерфейс веб-приложения для HR-отдела банка.
Прототип не является полноценной серверной системой, но демонстрирует структуру, внешний вид и базовую логику будущего приложения.

### 5.1. Главная страница системы

Файл:

```text
src/index.html
```

Главная страница прототипа содержит:

* боковое меню навигации;
* заголовок системы;
* приветственный блок;
* карточки с основными показателями;
* быстрые переходы к разделам;
* блок кадровых статусов.

Раздел показывает, как может выглядеть основная панель HR-специалиста после входа в систему.

### 5.2. Страница сотрудников

Файл:

```text
src/employees.html
```

Страница сотрудников предназначена для просмотра базы персонала банка.

На странице реализованы:

* таблица сотрудников;
* табельный номер;
* ФИО;
* должность;
* отдел;
* кадровый статус;
* кнопка открытия карточки сотрудника;
* кнопка изменения записи;
* поиск;
* фильтрация по подразделению;
* фильтрация по статусу;
* сброс фильтров.

Данные сотрудников находятся в файле:

```text
src/app.js
```

Пример структуры объекта сотрудника:

```js
{
  id: "1001",
  name: "Иванов Иван Иванович",
  position: "Менеджер по работе с клиентами",
  department: "Кредитный отдел",
  status: "Работает"
}
```

### 5.3. Поиск и фильтрация сотрудников

В файле `src/app.js` реализована простая логика поиска и фильтрации.

Поиск выполняется по следующим полям:

* табельный номер;
* ФИО;
* должность.

Фильтрация выполняется по:

* подразделению;
* кадровому статусу.

При изменении поисковой строки или выбранного фильтра таблица сотрудников обновляется автоматически.

Основные функции:

```js
renderEmployees(list)
filterEmployees()
getStatusClass(status)
```

Функция `renderEmployees()` отвечает за вывод сотрудников в таблицу.
Функция `filterEmployees()` отбирает сотрудников по заданным условиям.
Функция `getStatusClass()` назначает CSS-класс для визуального отображения статуса.

### 5.4. Карточка сотрудника

Файл:

```text
src/employee-card.html
```

Карточка сотрудника отображает подробную информацию о выбранном работнике.

На странице представлены:

* ФИО;
* табельный номер;
* должность;
* подразделение;
* кадровый статус;
* дата рождения;
* дата приема;
* стаж работы;
* контакты;
* рабочее место;
* тип занятости;
* график работы;
* результат проверки службы безопасности;
* история кадровых событий.

Данная страница демонстрирует структуру личного дела сотрудника в системе.

### 5.5. Подразделения

Файл:

```text
src/departments.html
```

Страница подразделений отображает основные отделы банка:

* HR-отдел;
* Кредитный отдел;
* Отдел рисков;
* IT-отдел;
* Финансовый отдел;
* Служба безопасности.

Для каждого подразделения указаны:

* название;
* краткое описание;
* количество сотрудников;
* руководитель.

Также добавлена сводная таблица подразделений с кодами отделов и типами подразделений.

### 5.6. Статистика

Файл:

```text
src/statistics.html
```

Страница статистики предназначена для отображения сводных данных по персоналу.

На странице представлены:

* общее количество сотрудников;
* количество работающих сотрудников;
* количество сотрудников в отпуске;
* количество новых сотрудников;
* распределение сотрудников по подразделениям;
* список кадровых статусов;
* сводный отчет в виде таблицы.

Для наглядности используются горизонтальные диаграммы, реализованные с помощью HTML и CSS.

## 6. Описание интерфейса

Интерфейс прототипа выполнен в стиле административной панели.

Основные элементы интерфейса:

* боковая навигационная панель;
* верхняя панель с названием раздела;
* карточки статистики;
* таблицы;
* фильтры;
* статусные метки;
* информационные карточки;
* блоки с диаграммами.

Цветовая схема выбрана в деловом стиле: темно-синий, синий, белый и светло-серый.
Такой стиль соответствует тематике банковской информационной системы и делает интерфейс визуально строгим и понятным.

## 7. Адаптивность

В CSS добавлены медиазапросы для корректного отображения интерфейса на экранах меньшей ширины.

При уменьшении ширины экрана:

* сетки перестраиваются в один столбец;
* боковая панель перестает быть фиксированной;
* карточки и таблицы адаптируются под доступную ширину;
* фильтры на странице сотрудников располагаются вертикально.

## 8. Публикация сайта

Для публикации сайта используется GitHub Pages.

В корне репозитория создан файл:

```text
index.html
```

Он выполняет переадресацию на главную страницу сайта проекта:

```text
site/index.html
```

Это позволяет открыть сайт через GitHub Pages по основной ссылке репозитория.

## 9. Работа с Git

В ходе выполнения проекта использовались отдельные ветки для разных задач.

Примеры веток:

```text
docs/project-description
site/project-website
site/github-pages
src/system-prototype
docs/technical-guide
```

Такой подход позволяет отделять работу над разными частями проекта и выполнять слияние изменений через Pull Request.

Основные действия:

* создание ветки;
* внесение изменений;
* коммит;
* отправка ветки на GitHub;
* создание Pull Request;
* слияние ветки с `main`.
